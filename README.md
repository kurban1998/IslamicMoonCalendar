# Исламский лунный календарь — Telegram Mini App

Мусульманский (хиджра) календарь. Главный экран — карточка **сегодняшнего**
дня по геолокации (фаза Луны, время намазов, хадис/аят, напоминания по
пятницам). Кнопка «Календарь» на карточке открывает отдельный экран
календаря — там можно только листать месяцы, по клику на день карточка не
открывается (это чисто просмотровый календарь).

## Структура проекта

```
telegram-hijri-calendar/
  Dockerfile                     — мультистейдж-сборка backend + фронтенд в wwwroot
  docker-compose.yml             — запуск одной командой (docker compose up --build)
  .dockerignore
  backend/IslamicCalendar.Api/   — ASP.NET Core Web API (.NET 9)
    Program.cs                  — эндпоинты /api/calendar/month, /api/day
    Models/                     — DTO-модели ответов
    Services/                   — интеграции с Aladhan API, AlQuran Cloud,
                                   локальный расчёт фазы Луны, хадисы
    Data/hadiths.json           — локальная база хадисов (Бухари/Муслим) — ДОПОЛНИТЕ
    appsettings.json            — настройки (координаты по умолчанию, метод расчёта)
  frontend/                     — статика мини-приложения (HTML/CSS/JS)
    index.html
    css/style.css
    js/app.js
```

Backend одновременно раздаёт и API, и статику фронтенда (`app.UseStaticFiles()`),
поэтому для простого варианта достаточно скопировать содержимое `frontend/` в
`backend/IslamicCalendar.Api/wwwroot/` — тогда всё будет работать на одном домене
без проблем с CORS. Либо разместите фронтенд отдельно и укажите домен backend
в `Cors:AllowedOrigins` (appsettings.json) и `API_BASE` в `js/app.js`.

## Используемые внешние API

- **Aladhan API** (https://aladhan.com) — бесплатный, без ключа:
  - `gToH` / `gToHCalendar` — перевод григорианских дат в Хиджру;
  - `timings` — время намазов по координатам.
- **AlQuran Cloud API** (https://alquran.cloud/api) — бесплатный, без ключа:
  - случайный аят с переводом (по умолчанию `ru.kuliev`, можно сменить в
    `appsettings.json` → `QuranTranslationEdition`, например на `ru.osmanov`).
- **Фаза Луны** считается локально по астрономической формуле (без API) — так
  надёжнее: публичные бесплатные API фаз Луны либо платные, либо нестабильны,
  а формула детерминирована и точна для отображения иконки. При желании можно
  подменить `MoonPhaseService` на обёртку над внешним API — интерфейс
  `IMoonPhaseService` для этого и предназначен.

## Город на карточке дня

Название города определяется обратным геокодированием с двумя бесплатными
провайдерами без ключей, по очереди:

1. **BigDataCloud** (основной) — не блокирует запросы с IP облачных хостингов,
   в отличие от Nominatim, поэтому взят первым;
2. **Nominatim** (OpenStreetMap) — резервный, если первый не ответил.

Если оба не смогли определить город — только тогда показываются координаты
как крайний случай. Результат кэшируется в памяти на 7 дней по координатам,
округлённым до ~1 км (`GeocodingService`), чтобы не дёргать внешние API на
каждое открытие карточки и не упираться в лимиты запросов.

Если у вас всё равно выводятся координаты — смотрите **Warning в логах
backend**: там будет точный ответ обоих провайдеров (`BigDataCloudGeocodingProvider`
и `NominatimGeocodingProvider` логируют статус-код и тело ответа при неудаче).

⚠️ Перед использованием в продакшене замените плейсхолдер контакта в
`Program.cs` (`UserAgent.ParseAdd(...)`, относится к Nominatim) на свой
e-mail/сайт — это требование
[политики использования Nominatim](https://operations.osmfoundation.org/policies/nominatim/).

## Производительность

- Конвертация дат по Хиджре, время намазов и геокодинг кэшируются в памяти
  backend (`IMemoryCache`) — повторная загрузка того же дня/месяца/локации
  не ходит в сеть заново.
- Таймауты внешних API снижены до 5–6 секунд, чтобы карточка/календарь не
  "зависали" надолго при сбое стороннего сервиса.
- Карточка дня (`loadTodayCard` в `frontend/js/app.js`) загружается один раз
  при открытии приложения — показывается спиннер поверх карточки, пока не
  придёт ответ, чтобы не мелькали пустые поля.
- Экран календаря при открытии/листании месяца одним запросом (`Promise.all`)
  подгружает сразу текущий + соседние месяцы — нужно для приглушённых ячеек
  на границах сетки (см. ниже), а благодаря кэшу на backend повторное
  открытие того же месяца почти мгновенное.

## Календарь: только просмотр, приглушённые соседние месяцы

Экран календаря (кнопка «Календарь» на карточке дня) — чисто просмотровый:
листаются месяцы стрелками, по клику на день ничего не открывается (никаких
карточек внутри календаря нет — только сама карточка сегодняшнего дня на
главном экране).

Сетка месяца показывает не только его собственные дни, но и захватывает
несколько дней предыдущего/следующего месяца, чтобы заполнить первую и
последнюю неделю сетки целиком (как в большинстве календарей). Эти
"чужие" дни помечаются классом `.other-month` и отображаются приглушённо
(`opacity: 0.32` в `frontend/css/style.css`) — визуально сразу понятно, где
границы выбранного месяца. При листании месяца приглушённым автоматически
становится всё, что не входит в новый текущий месяц (логика в `renderMonth`
в `app.js` пересчитывается на каждый вызов `loadMonth`).

## Запретные (священные) месяцы

В Исламе 4 запретных месяца по Хиджре: Мухаррам, Раджаб, Зуль-Каада,
Зуль-Хиджа (`HijriDate.SacredMonthNumbers` в backend, флаг `isSacredMonth`
приходит для каждого дня). Это отражено в двух местах:

- **Карточка дня** — переключается на розовую палитру вместо голубой
  (CSS-переменные переопределяются локально на `.day-card.sacred-month` в
  `frontend/css/style.css`) и показывает бейдж «Запретный месяц» под датой.
- **Сетка календаря** — ячейки дней запретных месяцев подсвечиваются розовым
  (`.day-cell.is-sacred`), в том числе если это ещё и «сегодня» или пятница —
  розовый имеет приоритет. Внизу экрана календаря есть легенда с цветами.

## Telegram-бот и команда /start

В проект добавлен фоновый сервис `TelegramBotHostedService`, который слушает
бота через long polling и на `/start` присылает кнопку, открывающую Mini App.

Настройка:

1. Получите токен бота у `@BotFather` (`/newbot`, если бота ещё нет).
2. У того же `@BotFather` создайте Mini App и получите его HTTPS-адрес
   (или используйте адрес, на котором развернут ваш backend + `wwwroot`).
3. Пропишите в `appsettings.json` (или через переменные окружения/секреты):

```json
"Telegram": {
  "BotToken": "123456:AA...ваш_токен",
  "MiniAppUrl": "https://ваш-домен.example"
}
```

4. Запустите backend (`dotnet run` или Docker) — бот стартует автоматически.
   Если `BotToken` пустой, сервис просто ничего не делает, остальное
   приложение работает как обычно (в логах будет предупреждение).

Long polling выбран специально: не нужен публичный HTTPS для *самого бота*
(в отличие от вебхука), поэтому `/start` можно проверить даже локально —
доступ извне нужен только самому Mini App, когда пользователь нажмёт кнопку.

Для продакшена с высокой нагрузкой обычно переходят на webhook — это можно
добавить отдельно (`ITelegramBotClient.SetWebhook` + HTTP-эндпоинт), но для
старта long polling проще и работает без дополнительной инфраструктуры.

Альтернативный/дополнительный способ — задать постоянную Menu Button у
`@BotFather` (`/mybots` → бот → Bot Settings → Menu Button), тогда кнопка
запуска будет всегда рядом с полем ввода, а не только после `/start`.

⚠️ Пакет `Telegram.Bot` периодически меняет сигнатуры методов между
версиями (например, `SendMessage` ↔ `SendTextMessageAsync`). Код написан под
актуальные на момент разработки версии; если после `dotnet restore`
подтянется другая — ориентируйтесь на ошибки компилятора, обычно достаточно
поправить пару вызовов в `TelegramBotHostedService.cs`.

## Хадисы

Файл `backend/IslamicCalendar.Api/Data/hadiths.json` — простой JSON-массив,
я закинул 8 стартовых хадисов (Бухари/Муслим) в вольном пересказе. Дополняйте
своими текстами и точными ссылками (номер хадиса, глава и т.д.), формат:

```json
{
  "id": 9,
  "source": "Аль-Бухари",
  "reference": "№ 6018",
  "textRu": "Текст хадиса на русском"
}
```

Цитата дня (`QuoteOfDayService`) выбирает хадис или аят детерминированно по
дате — один день всегда показывает одну и ту же цитату, и если API Корана
недоступен, автоматически подстраховывается хадисом.

## Запуск локально (без Docker)

```bash
cd backend/IslamicCalendar.Api
dotnet restore
dotnet run
```

Откроется на `https://localhost:xxxx`. Swagger — на `/swagger` (только в Development).
В этом варианте фронтенд из `frontend/` нужно вручную скопировать в
`backend/IslamicCalendar.Api/wwwroot/`, либо открыть `frontend/index.html`
отдельно и указать в `js/app.js` полный адрес backend в `API_BASE`.

## Запуск через Docker

Dockerfile лежит в корне репозитория, собирает backend и кладёт фронтенд
в `wwwroot`, так что после сборки всё раздаётся с одного адреса — API и
мини-приложение вместе, без проблем с CORS.

```bash
# из корня telegram-hijri-calendar/
docker build -t islamic-calendar .
docker run -p 8080:8080 islamic-calendar
```

Или через docker-compose:

```bash
docker compose up --build
```

Приложение будет доступно на `http://localhost:8080`. Настройки (метод расчёта
намазов, координаты по умолчанию и т.д.) можно переопределить переменными
окружения вида `IslamicCalendar__PrayerCalculationMethod=14` — см. примеры
в `docker-compose.yml`.

Для реального Telegram Mini App контейнер нужно развернуть на сервере с
HTTPS (сам по себе Docker HTTPS не даёт — понадобится обратный прокси вроде
Caddy/Nginx с сертификатом, либо PaaS с HTTPS из коробки — Railway, Render,
Fly.io и т.д.).

## Подключение к Telegram

1. Разверните backend на сервере с HTTPS (Telegram требует HTTPS для Mini Apps).
2. У @BotFather: `/newapp` (или `/mybots` → выбрать бота → Bot Settings → Menu
   Button / Mini App) и укажите URL вашего приложения.
3. В `appsettings.json` пропишите домен мини-приложения в `Cors:AllowedOrigins`,
   если фронтенд и backend на разных доменах.
4. Геолокация для времени намазов запрашивается через `Telegram.WebApp.LocationManager`
   (Bot API 8.0+) с fallback на `navigator.geolocation` и, если пользователь не
   даст доступ, backend использует координаты по умолчанию из `appsettings.json`.

## Что стоит доделать/проверить

- Проверить/поправить формулировки хадисов и добавить точные ссылки на издания.
- Уточнить `PrayerCalculationMethod` под свой регион (список методов —
  https://aladhan.com/calculation-methods; например, для России часто
  используют метод 14 — Spiritual Administration of Muslims of Russia).
- При желании добавить кэширование ответов Aladhan/AlQuran на backend
  (`IMemoryCache`), чтобы не дёргать внешние API на каждый клик.
- Названия сур на русском в `QuranService` — стандартные транслитерации,
  но при желании сверьте с предпочитаемым изданием перевода.
